## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP client → action/attachment tools | Untrusted: action_id, attachment content, filename from agent |
| Tool handler → Odoo | Odoo enforces ACL; OdooAccessError → ToolError |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-02-01 | Elevation of Privilege | action_execute_action | mitigate | Odoo enforces ir.actions.server execution rights per user credentials; OdooAccessError → ToolError(str(e)) surfaces denial without escalation |
| T-04-02-02 | Information Disclosure | attachments_download content_base64 | mitigate | Odoo ACL enforced at read_binary() level; OdooAccessError → ToolError before content returned; empty file guard returns error dict not empty base64 |
| T-04-02-03 | Tampering | attachments_upload datas field | mitigate | Odoo validates base64 field format; malformed content → OdooError → ToolError; no server-side path traversal possible (datas is a binary field, not a filename) |
| T-04-02-04 | Information Disclosure | ToolError message content | mitigate | raise ToolError(str(e)) — str(e) only, D-08 pattern; no repr(e) or traceback |
| T-04-02-05 | Spoofing | Per-user credential isolation | mitigate | Each tool call builds OdooClient from request.state.odoo_creds — no shared client, no cross-user bleed |
| T-04-02-SC | Tampering | cachetools package addition | mitigate | Package Legitimacy Audit in RESEARCH.md confirms cachetools 7.1.4 is [VERIFIED: installed in venv, 12+ years old, ~50M/wk downloads] |
