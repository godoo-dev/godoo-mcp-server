  <action>
  Create Dockerfile at the repo root using the two-stage pattern from RESEARCH Pattern 3.

  Builder stage (FROM python:3.14-slim AS builder):
  - Copy uv binary: COPY --from=ghcr.io/astral-sh/uv:0.7.12 /uv /bin/uv
  - WORKDIR /app
  - First RUN (dep layer, cache-friendly): mount-bind uv.lock + pyproject.toml without copying, run `uv sync --frozen --no-dev --no-install-project` with uv cache mount at /root/.cache/uv
  - COPY . /app
  - Second RUN: `uv sync --frozen --no-dev --no-editable` with uv cache mount — this embeds the package + skills into .venv/lib/python3.14/site-packages/godoo_mcp_server/

  Runtime stage (FROM python:3.14-slim — no AS alias needed):
  - WORKDIR /app
  - COPY --from=builder /app/.venv /app/.venv
  - Create non-root user: RUN groupadd -r godoo && useradd -r -d /app -g godoo -N godoo; USER godoo
  - ENV PATH="/app/.venv/bin:$PATH"
  - ENV HOST="0.0.0.0"
  - ENV PORT="8000"
  - HEALTHCHECK per D-05: --interval=30s --timeout=10s --start-period=15s --retries=3; CMD python -c "import urllib.request; urllib.request.urlopen('http://localhost:8000/healthz')" || exit 1
  - CMD ["godoo-mcp-server"] per D-06

  Do NOT: copy src/ into the runtime stage (--no-editable makes it unnecessary and adds dead weight); add uv to the runtime stage; use python:3.14-alpine (D-04 + CLAUDE.md prohibition); add EXPOSE directive without also documenting PORT env override; use gunicorn.

  Discretion choice (surfaced as chosen): non-root user added (two RUN lines) — security best practice per RESEARCH Open Question 3. GHCR will be the push target per RESEARCH Open Question 2 (GITHUB_TOKEN, no stored secrets). Base-image digest pinning: not applied in this Dockerfile (uv binary is pinned at 0.7.12; python:3.14-slim is not digest-pinned — acceptable for MVP, document as a future hardening option).
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Build context → builder stage | Full repo is sent as Docker build context; .dockerignore should exclude test artifacts and .git to reduce attack surface and build time |
| builder → runtime stage | Only .venv is copied; no build tools, no uv binary, no source tree leak into runtime |
| runtime → Odoo | Credentials arrive via env vars (ODOO_*); container does not store them — passed at `docker run` time |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-10 | Elevation of Privilege | Docker container running as root | mitigate | Non-root godoo user created in runtime stage (groupadd + useradd); USER godoo set before CMD |
| T-05-11 | Information Disclosure | uv cache or build secrets leaking from builder into runtime | mitigate | Runtime stage copies only /app/.venv — no cache mounts, no source, no uv binary in runtime layer |
| T-05-12 | Tampering | ghcr.io/astral-sh/uv image substitution (supply-chain) | mitigate | Pin to specific version `uv:0.7.12`; note that digest pinning is a future hardening option |
| T-05-13 | Denial of Service | HEALTHCHECK port mismatch (Pitfall 5) | mitigate | --start-period=15s allows uvicorn startup; document PORT override interaction in README |
| T-05-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed by this plan; runtime image has no package manager |
</threat_model>
