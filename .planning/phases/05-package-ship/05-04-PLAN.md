<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions → PyPI (OIDC) | Short-lived OIDC token exchanged for PyPI upload credential; scoped to one workflow run; cannot be reused |
| GitHub Actions → GHCR | GITHUB_TOKEN is job-scoped and auto-expires; packages: write permission gated by the job |
| workflow_dispatch → TestPyPI | Manual trigger requires repository Write access; cannot be triggered by external users |
| push v* tag → production PyPI | Tag push requires repository push access; protected branch rules can add an extra gate |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-30 | Elevation of Privilege | publish-pypi job runs on non-tag events | mitigate | `if: github.event_name == 'push' && startsWith(github.ref, 'refs/tags/v')` condition on both publish-pypi and publish-docker |
| T-05-31 | Tampering | Wrong Trusted Publisher environment name → OIDC exchange fails or succeeds with wrong scope | mitigate | environment: testpypi and environment: pypi must match the PyPI/TestPyPI configuration exactly; 05-05 manual task validates this before first run |
| T-05-32 | Information Disclosure | API token stored as GitHub Secret | mitigate | No PyPI API token stored; Trusted Publisher OIDC used exclusively (D-07) |
| T-05-33 | Tampering | publish-docker triggered before the wheel is verified on TestPyPI | accept | Docker build is from source (D-03) — independent of PyPI; TestPyPI gate (05-06) is a human verification step, not a blocking CI dependency |
| T-05-34 | Tampering | uv.lock tampered between build and publish | mitigate | build job uses `uv build` which reads the committed uv.lock; `--frozen` is implicit in uv_build backend; lock hash verified by uv |
| T-05-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed by this plan; workflow uses only uv and Docker actions |
</threat_model>
