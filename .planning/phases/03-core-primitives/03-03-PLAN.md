## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP client → discovery tools | Agent-supplied model name (string) for discovery_get_fields crosses here |
| discovery tools → OdooClient | Per-request credential material; fresh client per call |
| OdooClient → Odoo ir.model | Odoo's ORM handles ir.model access control (user must have read access) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-08 | Information Disclosure | fields_get response leaking e.data["debug"] | mitigate | raise ToolError(str(e)) — never e.data; test_list_models_no_traceback validates absence of "Traceback" |
| T-03-09 | Information Disclosure | Cross-user bleed via shared OdooClient | mitigate | Per-request OdooClientConfig construction; no _client module-level variable; grep audit in acceptance criteria |
| T-03-10 | Elevation of Privilege | discovery_list_models bypassing Odoo ACL | accept | search_read("ir.model") runs under the per-user credential context; Odoo enforces ir.rule and access control on ir.model reads; server does not sudo |
| T-03-11 | Information Disclosure | discovery_get_fields on sensitive model | accept | fields_get returns field metadata only (types, labels), not record data; access control for the field itself is enforced by Odoo ORM; no server-side filter needed at ASVS L1 |
| T-03-SC | Tampering | npm/pip/cargo installs | accept | No new packages; all deps already pinned |
