<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP client → record tools | Agent-supplied model, domain, ids, values cross here — forwarded to Odoo ORM |
| record tools → OdooClient | Per-request credential material; fresh client per call |
| OdooClient → Odoo ORM | Odoo's parameterized ORM is the trust boundary for domain/field injection |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-04 | Tampering | record_search domain arg | accept | Odoo's ORM uses parameterized queries; domain values are not string-interpolated into SQL. Server adds no own string interpolation. Odoo ORM is the trust boundary. |
| T-03-05 | Information Disclosure | ToolError message leaking e.data["debug"] | mitigate | raise ToolError(str(e)) — str(OdooRpcError) returns message field only (not e.data["debug"] traceback); test_search_no_traceback validates absence of "Traceback" in error output |
| T-03-06 | Information Disclosure | Cross-user bleed via shared OdooClient | mitigate | Per-request _make_config(creds) constructs OdooClientConfig from fresh request.state.odoo_creds; no module-level _client variable; grep audit in acceptance criteria |
| T-03-07 | Availability | record_search without limit on large model | mitigate | limit: int = 80 default in handler signature (D-06); agent must explicitly pass a higher value; documented in tool description |
| T-03-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed; all deps already pinned in pyproject.toml |
</threat_model>
