      @pytest.mark.e2e
      @pytest.mark.asyncio(loop_scope="session")

    Signature: async def test_agent_creates_partner_category(mcp_config_file: Path, odoo_harness: StartedOdooContainer) -> None:

    Docstring: "D-01/D-02: agent creates res.partner.category via real MCP transport; Odoo verify-back confirms the record exists. Skips cleanly if prerequisites absent (D-08)."

    Body:
    1. Generate unique tag name: tag_name = f"E2ETest-{uuid.uuid4().hex[:8]}" — this makes the verify-back search deterministic without cleanup (D-09/D-10)

    2. Build the agent prompt — MUST include exact model name, exact field name, exact value — per Pitfall 4:
       prompt = (
           f"Using the godoo MCP tools, create a new partner category (model: res.partner.category) "
           f"with the name field set to exactly '{tag_name}'. "
           f"Use the record_create tool. Return the id of the created record."
       )

    3. Launch the claude subprocess:
       proc = await asyncio.create_subprocess_exec(
           "claude", "-p", prompt,
           "--mcp-config", str(mcp_config_file),
           "--strict-mcp-config",            # REQUIRED — Pitfall 5: prevents dev MCP config leaking in
           "--allowedTools", "mcp__godoo__*",  # pre-approves only godoo tools; no bypassPermissions
           "--output-format", "json",
           stdout=asyncio.subprocess.PIPE,
           stderr=asyncio.subprocess.PIPE,
       )
       Do NOT use --permission-mode bypassPermissions — use --allowedTools scoped to mcp__godoo__* per RESEARCH.md anti-patterns.

    4. Wait for completion with timeout:
       try:
           stdout, stderr = await asyncio.wait_for(proc.communicate(), timeout=120.0)
       except asyncio.TimeoutError:
           proc.kill()
           pytest.fail("Agent subprocess timed out after 120s")

    5. Parse the JSON result:
       result = json.loads(stdout.decode())

    6. Auth skip guard (D-08 best-effort): inspect result before asserting. If result.get("is_error") is True, check for auth-related content in result.get("result", "") or stderr.decode(). If "auth" or "api key" or "ANTHROPIC" appears (case-insensitive), call pytest.skip with message f"Claude auth unavailable — skipping e2e test (D-08). Error: {result.get('result','')!r}". This turns auth failures into clean skips rather than hard failures.

    7. D-02 assertion — agent JSON result:
       assert result.get("is_error") is False, (
           f"Agent returned is_error=True. stderr={stderr.decode()!r}"
       )
       assert result.get("subtype") == "success", (
           f"Agent subtype not 'success': {result.get('subtype')!r}. stderr={stderr.decode()!r}"
       )

    8. D-02 verify-back — independent Odoo query (the authoritative proof, never just the agent's claim):
       records = await odoo_harness.client.search_read(
           "res.partner.category",
           domain=[["name", "=", tag_name]],
           fields=["id", "name"],
       )
       assert len(records) == 1, (
           f"Expected 1 partner category with name={tag_name!r}, found {len(records)}. "
           f"Agent result: {result.get('result', '')!r}"
       )

    No record cleanup (D-10: ephemeral testcontainer session; entire container is discarded at session end).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test-process→claude-subprocess | asyncio.create_subprocess_exec spawns the claude CLI; --strict-mcp-config prevents unintended MCP server loading; --allowedTools scopes tool permissions to godoo only |
| claude-subprocess→server-subprocess | HTTP over loopback TCP; credentials travel as X-Odoo-* headers in the MCP config |
| server-subprocess→Odoo-container | JSON-RPC over Docker bridge network; testcontainer throwaway credentials |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04.1-08 | Elevation of Privilege | claude invocation without --strict-mcp-config | mitigate | --strict-mcp-config is REQUIRED in the test; prevents dev's own MCP servers (potentially privileged tools) from loading into the test session |
| T-04.1-09 | Elevation of Privilege | --permission-mode bypassPermissions in claude invocation | mitigate | PROHIBITED: test uses --allowedTools "mcp__godoo__*" instead; bypassPermissions disables all safety checks beyond tool approval |
| T-04.1-10 | Information Disclosure | Agent result text logged in assertion messages | accept | Only tag_name (a UUID) and record count appear in assertion messages; no credentials, no Odoo URL in the assertion output |
| T-04.1-11 | Denial of Service | Unbounded claude subprocess runtime | mitigate | asyncio.wait_for(proc.communicate(), timeout=120.0); on TimeoutError: proc.kill() then pytest.fail; test does not block indefinitely |
| T-04.1-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed; test uses only stdlib + existing transitive deps |
</threat_model>
