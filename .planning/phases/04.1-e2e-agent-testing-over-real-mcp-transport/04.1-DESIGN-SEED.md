# Phase 4.1 — Design Seed (E2E agent testing over real MCP transport)

> Captured from the conversation that created this phase, so design intent survives a `/clear`.
> This is **input** for discuss/plan-phase, not a finished CONTEXT.md. Decisions marked **[LOCKED]** were
> explicitly chosen by the maintainer; everything else is a proposed default to confirm during discuss/plan.

## Why this phase exists
Phase 4 delivered the full tool surface, but **all** integration tests (`tests/integration/test_vertical.py`)
talk to the server **in-process** via `httpx.ASGITransport(app=...)`. Nothing exercises:
- the real Streamable-HTTP transport over an actual TCP socket,
- the `CredentialMiddleware` credential path as a real client would hit it,
- a real **agent's own tool-selection behavior** against the live `/mcp` endpoint.

This phase closes that gap with a true end-to-end test where a headless `claude -p` agent drives the tools.

## Locked decisions
- **[LOCKED] Harness = `claude -p` (headless Claude Code) as the MCP client**, run as a subprocess from a pytest test.
- **[LOCKED] HOST/PORT env vars** added to `src/godoo_mcp_server/__main__.py` — conventional names `HOST` / `PORT`
  (NOT `GODOO_MCP_*`), defaulting to `0.0.0.0` / `8000`. This is the enabling production change so the harness
  can bind an ephemeral port. (Current code hardcodes `0.0.0.0:8000` at `__main__.py:20`.)
- **[LOCKED] First e2e test = ONE agent-driven WRITE flow, verified in Odoo.** The agent creates a record
  (e.g. `res.partner` or `res.partner.category`) via a write tool; the test then **queries Odoo back through
  the harness** to prove the record actually landed — assert on BOTH the agent's JSON result AND the Odoo
  side-effect, not just the agent's claim of success.
- **[LOCKED] Opt-in / local-first.** New `@pytest.mark.e2e` marker, **default-deselected** (like the existing
  `integration` marker). Must **skip cleanly** (not error) when any of these is absent: Docker, the `claude`
  CLI on PATH, or Claude auth.
- **[LOCKED] Placement** = decimal Phase 4.1, before Phase 5 (Package & Ship). E2E proof before shipping.

## Proposed harness shape (confirm during planning)
1. Reuse the **session-scoped `godoo-testcontainers` `TestHarness`** fixture from
   `tests/integration/conftest.py` (real Odoo 17, `.url` / `._database` / admin password `admin`).
2. Spawn the server as a **real subprocess**: `python -m godoo_mcp_server` with `HOST=127.0.0.1`,
   `PORT={ephemeral}`, and Odoo creds injected via **`ODOO_*` env vars** (`ODOO_URL`, `ODOO_DATABASE`,
   `ODOO_USERNAME`, `ODOO_PASSWORD`) — `CredentialMiddleware` accepts env-var creds (precedence: X-Odoo-*
   headers > ODOO_* env). Env-var injection is simplest for a fixed-user subprocess.
3. **Poll `/mcp` for readiness** before launching the agent (TCP connect / HTTP probe loop with timeout) —
   there is no health endpoint yet; consider whether to add one.
4. Write a temp MCP client config and point the agent at it:
   ```json
   {"mcpServers": {"godoo": {"type": "http", "url": "http://127.0.0.1:{port}/mcp"}}}
   ```
5. Run: `claude -p "<task prompt>" --mcp-config <file> --allowedTools "mcp__godoo__*" --output-format json`
   (confirm exact flags for non-interactive permission handling — likely also a permission-mode / bypass flag;
   verify against current Claude Code CLI docs at plan time).
6. Assert: parse the agent's JSON result for success **and** independently read the created record back from
   Odoo via the harness.

## Open questions for discuss/plan-phase
- **Server credential model for the test:** env-var injection (fixed admin user, simplest) vs. X-Odoo-* headers
  in the MCP config (closer to the proxy's real per-user header-injection path). Seed leans env-var for v1.
- **Readiness probe:** add a lightweight health endpoint to the server, or poll the `/mcp` socket / do a real
  MCP `initialize` handshake? (A health endpoint is also useful for Docker in Phase 5.)
- **Auth/CLI detection for the skip guard:** how to detect "claude is usable" cheaply (e.g. `claude --version`
  + a `which claude` check; decide what signals "authenticated" without making a billable call).
- **Test runner command + docs:** likely `uv run pytest -m e2e`. Document it in README/dev notes.
- **Flakiness/timeouts:** the agent call is non-deterministic and network/LLM-bound — set a generous per-test
  timeout and keep the prompt tightly scoped to one deterministic write.
- **Cost note:** each e2e run makes a real (billable) Claude call. Keep the suite tiny and opt-in.
