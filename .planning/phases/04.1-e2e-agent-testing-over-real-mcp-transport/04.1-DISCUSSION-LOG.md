## A. Credential model for the test

| Option | Description | Selected |
|--------|-------------|----------|
| ODOO_* env vars | Inject ODOO_URL/DATABASE/USERNAME/PASSWORD into the subprocess env; fixed admin user; simplest; seed's v1 lean | |
| X-Odoo-* headers in MCP config | Credentials as X-Odoo-* headers in the claude MCP config; mirrors the proxy's real per-user path | ✓ |

**User's choice:** X-Odoo-* headers in MCP config
**Notes:** Diverges from the design seed's env-var lean. Chosen to exercise the same per-user
header-injection path `godoo-proxy` uses in production. CredentialMiddleware already supports
headers with headers>env precedence (`credentials.py:74-77`). RESEARCH FLAG recorded in CONTEXT.md:
confirm `claude` CLI `--mcp-config` supports per-server custom HTTP headers; fall back to ODOO_* env
injection if not. Temp config carries the throwaway testcontainers `admin` password into pytest `tmp_path`.

## B. Readiness probe + health endpoint

| Option | Description | Selected |
|--------|-------------|----------|
| Add /healthz, carved out of CredentialMiddleware | Lightweight unauthenticated route; deterministic; reusable as Docker HEALTHCHECK in Phase 5 | ✓ |
| Poll /mcp socket (no server change) | TCP/HTTP retry against /mcp; no code change but 401/406 makes ready signal ambiguous | |
| MCP initialize handshake | Real protocol-level readiness; most complex for v1 | |

**User's choice:** Add /healthz, carved out of CredentialMiddleware (Recommended)
**Notes:** Consistent with choice A — a health probe sends no credentials, so it must bypass
CredentialMiddleware (which otherwise 401s). Doubles as the Phase 5 Docker HEALTHCHECK.
